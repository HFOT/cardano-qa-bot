Date: 2026-09-06
Status: 承認済み・未実装

## なぜ作るか

サイト名が `What's Cardano?` でありながら、その質問に答えるトピックが無い。既存の7トピック
（取引所 / ウォレット / SPO / DRep / 詐欺 / ADAの価値 / Midnight）はすべて「何をするか」の
実務であり、その手前の「なぜそうするのか」が欠けている。

自由入力で「Cardanoとは」と打ってもキーワード辞書に該当が無く、ノーヒットになる。
サイト名の質問に答えられない状態だった。

## 対象読者

**ADAは持っているが、Cardanoが何なのかは知らない人。**

暗号資産そのものが初めての層は対象外とする。既存トピックがすべて保有を前提にしており、
そこだけ前提を変えると全体の一貫性が崩れるため。

## 背骨

**自分のADAから逆算する。**

「なぜステーキングで報酬が出るのか」「手数料は誰に行くのか」「なぜDRepなんて仕組みがあるのか」
——既存トピックでやっている行為の理由を遡る形にする。これにより、この1トピックが他の
7トピックすべての「なぜ」を供給し、サイト全体の導線が閉じる。

## 構造

新規ファイル `content/basics.js`。ID接頭辞は `basics-`（既存の `<topic>-root` 規約に合わせる）。

ホーム画面の**先頭**に追加する。サイト名の質問であるため。

```
basics-root  「Cardanoって結局なに?」
├─ basics-where   私のADAは、どこにあるの?          → wallet-root
├─ basics-reward  なぜ持っているだけで報酬が出るの?  → spo-root
├─ basics-fee     手数料は誰が受け取っているの?      → value-root
├─ basics-vote    なぜ投票の仕組みがあるの?          → drep-root
└─ basics-who     誰が作っていて、誰が決めるの?      （完結）
```

## 実装上の制約と対処

エンジンの `answer` ノードは `options` を無視する（`app.js` の `node.type === "answer"` 分岐が
`clearOptions()` を呼ぶ）。したがって他トピックへ送客する4ノードは `type: "choice"` とし、
解説本文を `text` に、送り先を `options` に1件だけ置く。

エンジンは「本文 → ボタン → 戻る/トップ」の順に描画するため、これで意図どおり動く。
**`renderNode` などのエンジン関数には手を入れない**（既存の方針を守る）。

送客先を持たない `basics-who` のみ `type: "answer"` とする。

### app.js への登録（3箇所）

トピック追加に伴う定型の配線のみ。エンジンのロジックは変えない。

1. 冒頭の import に `basicsContent` を追加（`?v=` は他と同じ番号）
2. `mergeNodes()` の `Object.assign` に `basicsContent.nodes` を追加
3. `HOME_NODE.options` の**先頭**に
   `{ label: "Cardanoって結局なに?", next: "basics-root" }` を追加

## 自由入力

`basics-root` の `keywords` に登録する:

```
"Cardanoとは", "カルダノとは", "Cardanoって", "カルダノって", "ADAとは"
```

マッチは `input.includes(keyword)` の最長一致。キーワードは空白を含まない単一トークンとする
既存ルールに従う。

## 内容

### 書かないもの

陳腐化する記述を最初から排除する。Yoroi（2026年4月にSecondFiへ改称、6月に侵害、7月に終了）を
初心者に推薦し続けていた事故を踏まえた方針。

- 具体的な報酬率(%) — 変動し、かつ期待値の約束に読まれる
- トレジャリー残高、DRep数、プール数 — 日々変わる。実数は既存のライブ連携に任せる
- 特定のウォレット名・取引所名
- 他チェーンとの優劣比較 — 相手の仕様変更で古くなる

### 各ノードの要旨

**basics-root**
「あなたはもうADAを持っている。では、それは何の上に乗っているのか」から入る。

**basics-where｜私のADAは、どこにあるの?**
ADAはウォレットの中に入っていない。台帳の上にあり、ウォレットが持つのはそれを動かす鍵だけ。
だからシードフレーズを失えば誰も助けられず、渡せば全部持っていかれる。→ ウォレット操作へ

**basics-reward｜なぜ持っているだけで報酬が出るの?**
取引の正しさを、預けられたADAの量で守る仕組み(PoS)。委任すると自分のADAは動かないまま
プールの重みとして数えられ、プールがブロックを作ると報酬が分配される。
**預けたADAはウォレットから離れず、ロックもされない** — 最も多い誤解なので明示する。→ SPO選びへ

**basics-fee｜手数料は誰が受け取っているの?**
手数料は消えるのでも運営会社に行くのでもない。一部はトレジャリーに積まれ、残りは報酬として
プールと委任者に回る。払う側と受け取る側が同じ集団の中にいる。→ ADAの価値へ

**basics-vote｜なぜ投票の仕組みがあるの?**
Cardanoには所有者がいない。誰も決められないなら決め方を決めるしかない。だから憲法があり、
DRepがいて、トレジャリーの使い道も投票で決まる。保有だけで投票権は生じるが、
行使するか委任するかは自分で選ぶ。→ DRep選びへ

**basics-who｜誰が作っていて、誰が決めるの?**
IOG・Cardano Foundation・EMURGO の三団体が開発と普及を担ってきた。ただし仕様変更を
三団体だけでは決められない構造へ移行済み。学術論文の査読を経てから実装する進め方も特徴。

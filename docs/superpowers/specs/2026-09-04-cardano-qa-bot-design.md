# Cardano Q&A ボット 設計

Status: Approved (pending user review of this doc)
Date: 2026-09-04

## 背景・目的

Cardanoコミュニティで日常的に発生する質問(ウォレット操作、SPO選び、DRep選び)は、内容がほぼ固定されている。
この固定コンテンツをQ&Aボット化し、繰り返し発生する説明コストを減らす。

`https://hfot.github.io/dialogue-verification-model/` は参考にしたが、あのページの「分岐理論」自体は採用しない。
参考にしたのは「会話形式で問題を解決していく見た目・体験」のみ。

## スコープ

**対象ユーザー**: Cardano初心者。専門用語を前提にせず、初めて触る人が迷わず読める粒度で回答文を書く。

初期スコープでカバーする3トピック:
- ウォレット操作・サポート(Daedalus/Eternl/Nami等の設定、送金、ステーキングの基本操作)
- SPO(プール)選び(手数料、サチュレーション、非集中化貢献度などの基準と手順)
- DRep選び(選定基準、委任手順、投票傾向の見方)

**コンテンツの厚み**: 各トピックにつき、初心者が疑問に思うであろう質問をできるだけ多く洗い出し、決定木の分岐(choiceノード)と回答(answerノード)を厚く作り込む。「後で埋める」前提の仮データではなく、実装フェーズで実際に使える分量の回答文を最初から書く。具体的な質問リストの洗い出しは実装計画(次工程)側で扱う。

スコープ外(将来検討):
- AI API連携(LLMによる自由応答・要約)
- 自然言語の意図解析(NLU)
- 多言語対応

## アーキテクチャ

完全静的サイト。バックエンドなし、外部API呼び出しなし。GitHub Pagesにそのままデプロイ可能。
HTML/CSS/素のJSのみ(ビルドステップ・フレームワーク不要)。

```
cardano-qa-bot/
├── index.html
├── styles.css
├── app.js              # チャットUIエンジン・決定木の解釈・キーワードマッチング
└── content/
    ├── wallet.js        # ウォレット操作の決定木データ
    ├── spo.js           # SPO選びの決定木データ
    └── drep.js          # DRep選びの決定木データ
```

## データ構造(決定木)

各トピックファイルは、ノードのマップをexportする。ノードは3種類:

- **choice**: 質問文 + 選択肢ボタン。選ぶと `next` で指定した次ノードへ遷移。
- **message**: BOTが一言添えるだけの中継ノード。表示後、自動的に次ノードへ進む。
- **answer**: 最終回答。終端ノード。`keywords` 配列を持つ(自由文マッチング用)。「トップに戻る」「前の質問に戻る」ボタンを常設。

```js
// content/spo.js の例
export default {
  id: "spo-root",
  nodes: {
    "spo-root": {
      type: "choice",
      text: "プール選びで気になるのは?",
      options: [
        { label: "手数料について", next: "spo-fee" },
        { label: "非集中化への貢献", next: "spo-decentralization" },
      ],
    },
    "spo-fee": {
      type: "answer",
      text: "(手数料に関する回答文。後で執筆)",
      keywords: ["手数料", "fee", "margin", "コスト"],
    },
    "spo-decentralization": {
      type: "answer",
      text: "(非集中化に関する回答文。後で執筆)",
      keywords: ["サチュレーション", "saturation", "分散", "非集中化", "pledge"],
    },
  },
};
```

起動時に3ファイルの `nodes` をマージし、キーワードマッチング用の単一インデックス(`keyword → nodeId`)を作る。

## UI/UX

チャットバブル形式。BOT発言は左寄せ、ユーザーの選択・入力は右寄せでエコー表示する。

**入力は2系統を常設**:
1. ボタン選択(メイン導線) — choiceノードの選択肢がその都度表示される
2. 自由文入力欄(下部に常設) — いつでも自由文を打ち込める

**自由文入力時の処理(キーワードマッチング、AI不使用)**:
1. 入力文字列を全キーワードインデックスと照合(部分一致)。ノードごとに一致したキーワード数を数える
2. 最多一致数のノードが1件だけ → そのanswerノードへジャンプし、回答冒頭でヒットしたキーワードを拾って表示する
   (例: 「"手数料" についてですね」→ 続けて回答本文)
3. 最多一致数のノードが複数(同数タイ) → 候補をボタンで提示し、ユーザーに選ばせる(ボタン導線に合流)
4. **1件もヒットしない(一致数0) → 「うまく聞き取れませんでした。下の選択肢から選んでください」と表示し、現在地(または最上位3択)の選択肢ボタンを再表示する。**AI的な当て推量やフリーテキスト応答は行わない。

**ナビゲーション**:
- トップ画面: 「ウォレット操作」「SPO選び」「DRep選び」の3入口
- 「戻る」ボタンを常設(行き止まり回避)
- 「トップに戻る」ボタンをanswerノードに常設

## コンテンツ運用フロー

回答文・キーワードはユーザーが `content/*.js` に直接書いて更新する。
`git commit` → GitHub Pagesに自動反映、という運用。

将来「ウォレット/SPO/DRep」以外のジャンルを追加する場合も、同じ決定木エンジンに新しい `content/*.js` を1ファイル足すだけで拡張できる。

## テスト方針

自動テストは設けない(静的サイト・ロジックも単純なため)。
実装後、ブラウザで以下を手動確認する:
- 各トピックの決定木を最後まで辿れる(行き止まりなし)
- 自由文入力: キーワード単一ヒット/複数ヒット/ノーヒットの3パターン
- 「戻る」「トップに戻る」の遷移
